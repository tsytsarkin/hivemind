# Hivemind 1.5.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship project-user-governed capability grants, one canonical Claude identity, discoverable agent settings and version, honest model status, and updated peer-file guidance.

**Architecture:** Extend the existing per-project SQLite catalog and agent capability records with separate definition and grant approvals; enforce eligibility at storage and MCP boundaries. Canonicalize `claude-code` at address ingress and run a per-project, restart-safe migration of persisted references. Keep the existing Starlette console and client skills, exposing server metadata to the browser.

**Tech Stack:** Python 3, SQLite, Starlette/MCP, pytest/httpx, browser JavaScript/CSS, npm web tests.

**Spec:** `docs/superpowers/specs/2026-09-26-hivemind-1.5.2-design.md`

## Global Constraints

- Existing user token shared by console and agents; supported-MCP restriction, not adversarial HTTP authorization.
- `max_parallel_tasks` means 1–20 concurrent task claims, never session count.
- Old `claude-code` clients keep accessing the canonical `claude` mailbox and their work; preserve message ids, lease tokens and instruction state.
- Existing live claims survive approval migration, pending tags cannot enable a new claim; do not mutate real project DBs in tests.
- Real model names only when exposed by the host; absent model displays `Model unknown`.
- Chat retention stays 24 hours; graph tasks remain durable. Version is 1.5.2.

## File structure

`capabilities.py` owns the catalog and grant approval API; `db.py`/`schema.sql` own additive schema and bootstrap migration; `graph_tasks.py`/`assignments.py` enforce eligibility; `capability_tools.py` rejects agent grant writes while preserving independent agent task-config writes; `ui_capabilities.py`/`ui_api.py` own project-user edits. A focused new `client_alias_migration.py` owns legacy address migration; `chat.py` owns address normalization and compatible chat retry handling. `ui_app.py` supplies server version; `ui_assets/index.html`, `app.js`, `styles.css` provide navigation/settings and known/unknown model display. Tests remain in the matching existing test files, with a separate alias migration test. Both shipped `hivemind` skills and release metadata change last.
