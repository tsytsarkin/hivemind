# Hivemind 1.4.0 Durable Chat and Rooms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist project-scoped offline direct messages and public topic rooms for 24 hours, with stable agent addresses, catch-up and presence.

**Architecture:** New project SQLite chat tables own messages/rooms/subscriptions/cursors; existing WebSocket transport pushes notification-only frames. New canonical chat tools and listener credentials coexist with explicit legacy ephemeral bus tools. Neither private DM body nor its ID enters the legacy hub recent lookup.

**Tech Stack:** Python 3.11+ server, SQLite WAL, FastMCP, Starlette WebSocket, stdlib-only Claude/Codex listeners, pytest/anyio.

**Spec:** `docs/superpowers/specs/2026-09-25-hivemind-1.4.0-durable-agent-collaboration-design.md`

## Global Constraints

- Every MCP call explicitly names a project; private project ACL applies before reads or writes.
- Stable mailbox identity = authenticated username + authenticated device + client; session adds sessionid. Never split the display label to recover fields or truncate identifiers.
- Use `StableAddress = tuple[str, str, str]` for all storage and comparisons, with separate authenticated user/device/client columns; hyphens in any component must not cause two addresses to collide.
- Persist and acknowledge before attempting WebSocket notification. Exactly 24 hours of DM/room history from server creation time; no silent early eviction or implicit room creation.
- Byte caps: 256 KiB body; per project 512 MiB counted bytes and 100,000 messages; page maximum 100. New sends require idempotency keys.
- Legacy `bus_connect`, `bus_send`, `bus_message` stay clearly ephemeral; new durable messages must not enter their memory queues or recent cache.
