# Hivemind 1.5.0 Web Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a polished, optional, project-scoped Hivemind browser console on a dedicated port with existing-token login, agent DMs, room/team controls, task statuses, and project-local instructions.

**Architecture:** Run a second Starlette ASGI listener in the existing server process, sharing its project registry, identity store, and the coordination services from the backend plan. Browser requests use server-side cookie sessions and same-origin project APIs; the agent MCP port and its private DM reads are unchanged.

**Tech Stack:** Python 3.11+, Starlette/uvicorn, SQLite, HTML/CSS and vanilla ES modules; pytest/httpx. Dev-only browser smoke tests use Playwright/Chromium.

**Spec:** `docs/superpowers/specs/2026-09-26-hivemind-1.5.0-project-console-and-teams-design.md`

## Global Constraints

- This plan follows `docs/superpowers/plans/2026-09-26-hivemind-1.5.0-coordination-backend.md` and calls its tested service functions; never duplicate their authorization/state transitions in JavaScript.
- Web UI is enabled by default at `127.0.0.1:8788` but can be disabled in `<data-dir>/hivemind.toml`; MCP remains on its own configured port.
- Login accepts existing **server-level user tokens** only; no password database, legacy project token, browser `localStorage` bearer, or server-wide administrator role.
- Each project view/action is restricted by `can_access`; any project user may read all that project's DMs in the **explicit console API**. Agent-facing MCP inbox remains sender/recipient private.
- Unresolved instructions stay in their own project queue; ordinary room/DM messages retain their 24-hour expiration.
- Token revocation is effective on the next UI request and at most 30 seconds into a live update stream.
- Test interpreter on this machine: `/tmp/hivemind-1.4-env.8TNoQZ/venv/bin/python`. Run host-neutral tests with `env -u CODEX_THREAD_ID -u CODEX_SESSION_ID`.
- Each task: red test → minimal implementation → focused green tests → staged diff check → narrow commit.

## File responsibilities

- `config.py`, `app.py`: TOML/env configuration and two same-process listeners with independent ports/lifecycles.
- `ui_sessions.py`: server-side opaque browser sessions and CSRF tokens; stores only bearer fingerprint, not raw token.
- `ui_auth.py`: resolve per-request session, revocation, identity context, origin/CSRF and project ACL.
- `ui_app.py`: UI routes and static asset entry, no MCP mounting or unprotected project URL.
- `ui_chat.py`: explicit project-wide console transcripts/human DM adapter, not the agent `chat_inbox` API.
- `ui_api.py`: bounded roster/rooms/tasks/queue JSON read/write adapters over backend-plan services.
- `ui_assets/index.html`, `app.js`, `styles.css`: semantic, accessible responsive front end without build-time runtime dependencies.
- `test_ui_config.py`, `test_ui_auth.py`, `test_ui_chat.py`, `test_ui_api.py`, `web-tests/`: focused server and browser tests.
