# Hivemind 1.4.0 Graph Task Heartbeats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep optional graph task claims reclaimable after lost workers, without producing a graph revision on every heartbeat.

**Architecture:** Project SQLite holds a persistent `task` marker and sidecar liveness/lease state keyed by graph `node_id`; actual structured task nodes and their status revisions live in the existing graph. Task APIs atomically fence claims, write real state transitions and link to explicitly created public rooms.

**Tech Stack:** Python 3.11+, SQLite WAL, Hivemind graph/versioning, FastMCP, pytest and existing Claude/Codex plugin skills.

**Spec:** `docs/superpowers/specs/2026-09-25-hivemind-1.4.0-durable-agent-collaboration-design.md`

**Dependency:** Execute the durable-chat plan first: `docs/superpowers/plans/2026-09-25-hivemind-1.4.0-durable-chat.md`.

## Global Constraints

- User-facing statuses are exactly `unclaimed`, `in_progress`, `complete`. Graph task nodes (including completed tasks) have no chat TTL; only DMs/room messages expire after 24h.
- A claim defaults to 5-minute heartbeats and expiry 1h after the last accepted beat. Agent-selectable bounds: 30s–8h interval, expiry 1min–24h and at least twice the interval; an actively renewed task can run beyond 24h.
- Claiming is optional: a marked node can accept multiple non-exclusive activity heartbeats; exclusive claim is opt-in. Each valid beat updates sidecar only, never `tx`/`node_version`.
- Real graph status changes use versioned writes with provenance and atomic lease/status transactions; a stale claim token cannot renew, release or complete; expiry and takeover must be fenced.
- The room must be explicitly created by an agent before offering its graph task. Active room workers post genuine progress around every 15 minutes; no fabricated posts and no human acknowledgement requirement.
- Follow `superpowers:test-driven-development` (including its `writing-good-tests.md` reference), `superpowers:writing-skills`, and `superpowers:verification-before-completion`. Use clean baseline `env -u CODEX_THREAD_ID -u CODEX_SESSION_ID /tmp/hivemind-1.4-env.8TNoQZ/venv/bin/python -m pytest -q`.

    with db.write("a", "register work type") as tx:
        schemas.define_type(tx.cur, tx, "node", "work_item",
                            {"type": "object", "additionalProperties": True}, status="active")
    node_id = graph.upsert_node(db, "a", "work_item",
                                {"title": "Inspect parser", "status": "unclaimed"})["node_id"]
    graph_tasks.enable(db, "a", node_id)

    new = graph_tasks.claim(db, "b", node_id, "nikt-mac-claude", now=4601)

        graph_tasks.complete(db, "a", node_id, old["claim_token"], now=4602)
