# Hivemind 1.5.0 Coordination Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every Hivemind project per-room managers, mandatory fenced task assignments, self-advertised capability eligibility, and a project-local durable human instruction queue.

**Architecture:** Add narrow services over each project's existing SQLite database and expose them through project-aware MCP tools. Keep graph tasks as graph nodes, with manager/assignment/capability/instruction state as project-local sidecars; share these services with the separate-port browser API in the companion UI plan.

**Tech Stack:** Python 3.11+, SQLite, existing MCP SDK, Starlette test client, pytest.

**Spec:** `docs/superpowers/specs/2026-09-26-hivemind-1.5.0-project-console-and-teams-design.md`

## Global Constraints

- Existing graph task statuses stay `unclaimed`, `in_progress`, `complete`; `assigned / waiting` is a derived UI state, not a new schema enum.
- A room has exactly zero or one manager, bound to a stable `(user, device, client)` address, never a session-display string.
- MCP user/device comes from the token; `client`/`session_id` is self-declared and cannot attest two clients sharing that token.
- All instruction, manager, assignment, and capability data and reads are **project-local**; an agent never receives another project's queue.
- Claim heartbeat defaults remain 300 seconds / expiry 3600 seconds; max expiry 24 hours; no heartbeat before assigned agent starts.
- Project chat messages still expire after 24 hours; unresolved instructions and completed graph tasks do not.
- No remote shell or process execution. Rejected races return `Conflict`, never silently override a newer generation.
- Test interpreter on this machine: `/tmp/hivemind-1.4-env.8TNoQZ/venv/bin/python`; for host-neutral tests use `env -u CODEX_THREAD_ID -u CODEX_SESSION_ID` before the interpreter. Baseline: 682 tests passed.
- Each task: red test → minimal implementation → focused green tests → staged diff check → narrow commit. Do not rewrite unrelated user changes.

## File responsibilities

- `schema.sql`, `db.py`: additive project-local tables/migrations; old projects and new projects converge.
- `capabilities.py` + `capability_tools.py`: self-advertised stable-agent tag registry and its MCP boundary.
- `teams.py` + `team_tools.py`: room memberships, manager promotion/handoff, and actor-scoped authorization.
- `graph_tasks.py` + `graph_task_tools.py`: durable required tags, task schema fallback, assignment/claim/fencing.
- `instructions.py` + `instruction_tools.py`: project-local instruction queue and recipient-only MCP lifecycle.
- `chat.py`: reuse stable addresses, room/subscription storage and existing 24-hour session logic; add only targeted read helpers.
- `mcp_tools.py`: attach the three small tool modules; no monolithic new tool bodies.
- `packages/hivemind-server/tests/test_capabilities.py`, `test_teams.py`, `test_assignments.py`, `test_instructions.py`: service+MCP tests, migration and concurrency fixtures.
